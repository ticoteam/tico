# Cut a post into channel versions

When to use: after a draft passes its claim check and the team needs a social post, a short version, a newsletter blurb or a caption for a channel.

Steps:
1. Name the one point of the piece in one sentence. Every version carries that point and no second one.
2. For each channel, write three things: the caption or opening line (the hook a reader on that channel stops for), the ask (the one next step), and the proof (the fact or example that supports the point).
3. Keep the claims identical across versions. If a version needs a new claim, run the claim check on it first.
4. Shorten by cutting, not by rewriting: remove a sentence, then a clause, before you change a word.
5. Check each version alone. It must make sense to someone who has not read the long piece.
6. Save each version as its own file in the piece's folder, with its channel and length in the first line.
7. Note in the task which versions exist and which are still missing.

Checks before you finish:
- Each version has one point, one ask and the same claims as the long piece.
- Each version was checked on its own, not only as a cut.
- No version carries a claim that failed the claim check.
- The task note lists the missing versions, if any.

Example (generic): "Long piece: 'Why classes have empty spots after cancellations', one point: a late cancel is only a loss if nobody is told the spot is free. Versions: a 60-word social post (hook: the spot is free for 20 minutes), a 3-line newsletter blurb (ask: the reminder checklist), a caption with the same proof line, the 14-ticket sample described as a sample. No version repeats the 'guaranteed results' claim, which failed the check."
