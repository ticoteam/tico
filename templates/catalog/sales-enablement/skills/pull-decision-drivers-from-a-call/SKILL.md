# Pull decision drivers from a call

When to use: when you write a win/loss note for a deal, or add a deal to `knowledge/win-loss.md`.

Steps:
1. List the calls you will read before you read them, with their dates and whether each was imported.
2. Read the buyer's turns first. Write each thing the buyer valued, feared, compared, or said decided the outcome. Note the buyer-side role of the speaker.
3. Write each driver as a quote or a close paraphrase with the call and timestamp. A driver with no timestamp is your paraphrase and is labelled as one.
4. Mark the seller's own explanations apart. "Too expensive" in a seller's note is a claim to test against the buyer's words, not a driver.
5. Compare with the recorded win or loss reason in the CRM. Where they differ, write both and say which the calls support. Send the correction to the deal's owner and to `sales-ops`.
6. Keep four to six drivers per deal. If the calls show fewer, say so.
7. Add the drivers to `knowledge/win-loss.md` with the count of deals per driver, wins and losses kept apart.

Checks before you finish:
- Each driver has a buyer quote or a labelled paraphrase, a call and a timestamp.
- Seller explanations are not counted as buyer drivers.
- The recorded reason is not dropped when the calls disagree with it.
- Patterns are counted; a driver from one deal is labelled an anecdote.

Example (invented, for illustration): "Example Studio, lost 2026-09-18. Driver: 'Our front desk would have to learn a second system before we could switch' (buyer's operations lead, call 2026-09-02, 14:20). The seller's note says price. The calls do not support price as the main driver. CRM reason: price. Both are written; the correction goes to the owner and sales-ops."
