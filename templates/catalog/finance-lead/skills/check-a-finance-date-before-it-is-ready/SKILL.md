# Check a finance date before it is ready

When to use: when you write the next-14-days section of the weekly summary, or when a finance date may be missed.

Steps:
1. List every date in the window from `knowledge/finance-calendar.md` and `hub calendar list`. Note where each came from and
   when it was last confirmed.
2. For each date, name the owner from `knowledge/team.md` and the inputs it needs (for example the payroll register, the tax
   amount, the bank export). Mark each input ready, open or not supplied.
3. Check the last confirmation. A date last confirmed more than 30 days ago, or read from a calendar that is itself stale, is
   marked "to confirm".
4. Treat an empty read with care. An empty calendar read marked stale is not "no events". Say "not read", and say what was checked.
5. Flag a date as at risk when it is within five working days with an input still open. The owner hears it on the first line of the summary.
6. Close the loop: when an input arrives, update the calendar row with its date and source.

Checks before you finish:
- Each date names its owner and its input status.
- Stale or unread sources are labelled, not counted as clear.
- Every at-risk date is on the summary's first page.
- No date was invented; a date with no source is "to confirm".

Example (invented, for illustration): "10-15, estimated tax payment (owner: Tax Specialist). Input open: the amount from the
accountant, not yet supplied. At risk: five working days out. Calendar last confirmed 2026-09-18, so to confirm."
