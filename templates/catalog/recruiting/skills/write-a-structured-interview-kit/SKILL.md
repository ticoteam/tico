# Write a structured interview kit

When to use: when a role has criteria but no kit, when a kit has questions without a scoring guide, or when an interviewer
asks what a good answer looks like.

Steps:
1. Start from the required criteria in `knowledge/roles/<role>.md`. Each question tests one criterion. A preferred
   criterion gets a question only when the work needs it in the first six months.
2. Write four to six questions. Ask for past work and specific situations ("tell me about a time you..." or "what did you
   do when..."). Avoid hypotheticals and questions about opinions of the team.
3. For each question, write one follow-up that asks for the detail the score depends on: what the candidate did, what
   happened, and how they checked it.
4. Write a four-level scoring guide for each question: **poor**, **borderline**, **solid**, **outstanding**. Each level
   names what the answer must contain. It does not describe how the person sounds.
5. If the role's output can be shown in a short sample (an email, a call plan, a short analysis), add one work task.
   Give every candidate the same task and the same time limit. Score it against the written guide, not against the best
   sample you have seen.
6. Set the scoring rule: each interviewer writes scores before anyone speaks, scores are compared afterwards, and a gap
   of two levels or more is discussed.
7. Save the kit in the role file. Mark anything the hiring manager has not confirmed.

Checks before you finish:
- Every question maps to a stated criterion.
- Every question has a four-level scoring guide.
- No question asks about family, health, age, origin, religion or another protected characteristic, or a proxy for one.
  No question asks what the candidate earns now.
- Every interviewer for the role gets the same kit.

Example (generic, invented): Role: Customer Support Specialist. Criterion: writes a reply that answers the question in its
first two sentences. Question: "Tell me about a reply you wrote to an upset customer. What did its first two sentences say?"
Follow-up: "What did you check before you sent it?" Poor: no answer to the question, or an apology with no next step.
Borderline: solves the problem, but the first line is an apology. Solid: answers in the first two sentences and gives the
next step with a date. Outstanding: also states the limit of the fix, so the customer is not surprised later.
