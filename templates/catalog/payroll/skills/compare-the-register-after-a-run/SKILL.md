# Compare the register after a run

When to use: the day after a pay date, or when a human asks for a post-run check on a register.

Steps:
1. Get the register for the run and the documented summary for that run. Note both dates. If the register is not final, say so first and label the
   result "preliminary".
2. Match people by employee id and name. Anyone in the register and not in the expected roster, or the reverse, is the first difference.
3. For each person, compare the gross and the listed items: rate, hours and overtime, bonus, commission, deductions. Each mismatch goes on
   the list with what was expected, what the register shows and the source.
4. Classify each difference: timing (the change was effective next period), data (the input or the source is wrong), or processing
   (the register did not apply what was approved). Do not guess a class; use "unknown" when the source does not show it.
5. For each difference, propose the correction for the next run or an off-cycle run, and name who decides. You do not enter it.
6. Write the result: "Pass" with the count checked, or the count of differences with one line each.

Checks before you finish:
- Every person in either list is accounted for.
- Each difference has its expected value, register value and source.
- Nothing was corrected in the payroll system or the bank.
- A preliminary register is labelled preliminary in the first line.

Example (invented, for illustration): "Run 2026-10-09: 2 differences. E-1042: overtime 4.5 hours in the register, 3.0 on the approved timesheet (timesheet 2026-10-12). Data class. Proposed correction for the next run; owner: Payroll Specialist. E-2210: bonus of 500 not in the register; approval dated 10-08, so timing class."
