# Run a data request to its deadline

When to use: when a request to access, correct, delete or move personal data arrives on a task or in the privacy mailbox.

Steps:
1. Record the date the request reached the team (not the date the task was made), its kind and the requester's first name and request id.
2. Find the requester's place. Look up its rule in `knowledge/privacy-practice.md`. If no rule is written for that place, say so and stop the day count until one is written.
3. Work out the deadline and write the arithmetic, for example "received 2026-09-19, one month, deadline 2026-10-19".
4. Check identity and scope. If identity or clarification is needed, ask for the minimum on the task, and record the date asked.
5. Write one line per system from `knowledge/processing.md`: what to search for, what to do, who runs it, and what must be kept (for example, invoices). Create one task per system, with the due date in its title, 5 days before the deadline.
6. If an extension may be needed, a human decides it and records who and why. The notice to the requester is sent before the first period ends.
7. When every system is done, draft the reply (what was done, what was kept and why) on the task. It goes out only when a person has turned mail sending on and the task asks for it.

Checks before you finish:
- The received date, the deadline and the arithmetic are on the row.
- No personal detail beyond first name and request id is in the report.
- Each action on a system has a task, and a granted Tool if the work uses one.
- The row shows the date the reply was sent, and only once it has been delivered. The request is not done before that.

Example (invented, for illustration): "DR-014, access. Received 2026-09-19. Requester's place: EU. Deadline 2026-10-19 (one month from receipt). Support desk export due 2026-10-14, five days before the deadline."
