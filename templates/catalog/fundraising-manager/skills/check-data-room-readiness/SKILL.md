# Check data room readiness

When to use: when the checklist is first built, before a batch of investor meetings, or after an investor asks for a document.

Steps:
1. List what the data room should hold: a common starting set (company overview, deck, model, financial statements, cap table
   summary, customer metrics, summary of key contracts, team, legal and IP status) plus what investors have asked for, from
   `knowledge/investor-notes.md`. The team confirms the starting set; record any item it drops.
2. For each item, record: in or out, the file's version and date, the owner, the access tier for each investor group, and
   whether it needs an NDA first.
3. Check versions, one document at a time. A document is stale only when a newer version replaces it, or a later change
   affects what it says (a new model, cap table or financial close may; a signed contract or a historical legal document
   often does not). Name the replacement, or the change, for each stale document.
4. Check sensitivity. Customer names, contracts and personal details wait behind an NDA or a redaction. Say so on the row.
5. Report the gaps in one list: missing, stale, unowned, blocked by an NDA. Each has an owner and the date it is needed
   (the next meeting that asks for it).
6. Share nothing and add no one. Access changes wait for a person's go-ahead, per AGENT.md.

Checks before you finish:
- Every row has an owner and a date.
- Every stale document is named with its replacement, or the change that makes it stale.
- Nothing is marked "in" without a file that exists in the record.
- No access was granted or changed.

Example (invented, for illustration): "Gaps before Wednesday's Harbour Capital meeting: 1) churn cohort table, missing (owner
Ravi, needed 2026-10-07). 2) Financial summary dated 2026-06-30, stale; the Q3 close replaces it (owner Odile). 3) Customer
reference list, blocked: no NDA signed yet."
