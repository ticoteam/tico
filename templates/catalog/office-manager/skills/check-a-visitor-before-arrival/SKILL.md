# Check a visitor before arrival

When to use: the day before each visitor or office event on the calendar, and again when a visit is added at short notice.

Steps:
1. Take the visitor or event from `hub calendar list` for the next 7 days: date and time, host, room, expected number of
   people, and any catering or access note on the invite.
2. Run the host checklist in `knowledge/visitors.md`, one line at a time:
   - reception told the name, the time and the host;
   - room booked for the time and the number of people;
   - guest Wi-Fi details ready, if the visitor needs them;
   - catering ordered or confirmed, if any, with the number and the cut-off time.
3. Mark each line done (with the time you checked), not done, or not applicable. A line is not done because the host said
   it is; check it.
4. Name each missing item and its host on the weekly page under "Visitors and events". Do not fill it in yourself unless a
   granted Tool allows the booking and the task asks for it.
5. Access is not part of this check. Building access (badges, keys, door codes, alarm codes) belongs to its admin. Say on
   the task who meets the visitor at reception, and never give a key, badge or code.
6. Keep only what the visit needs: the visitor's name, company, host, time and the sign-in. Delete the visit record 30 days
   after the visit, as `knowledge/visitors.md` says.

Checks before you finish:
- Each line of the host checklist is marked done, not done or not applicable, with a time checked.
- Each missing item is named with its host.
- No access, key or code appears in the task, the page or the knowledge files.
- Visit records older than 30 days after the visit are deleted.

Example (invented, for illustration): "Tuesday 10:00, two people from a partner studio, host Dana, room 3. Reception: not
told yet (checked 2026-09-28, 16:10). Room 3 booked. Guest Wi-Fi: not needed. Catering: not needed. Missing: reception,
with Dana. Access: reception meets them; no badge given."
