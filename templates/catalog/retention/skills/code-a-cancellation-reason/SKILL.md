# Code a cancellation reason

When to use: for every cancellation, downgrade or pause request, before any offer is matched.

Steps:
1. Quote the customer's own words for the reason, with the date and the channel. Keep the exact words in the reasons log.
2. Pick one code from `knowledge/save-policy.md` that matches those words. If two fit, take the one the customer named first, and note the other.
3. Do not code from what you suspect (a competitor's price, a review they read). A suspicion goes in the note, not the code.
4. If the customer gave no reason, code it "not given". The reply may ask once, in one line, and never as a condition of cancelling.
5. If the words fit none of the codes, code it "other" and quote the words. Three "other" lines on the same theme in a week go to the weekly report as a candidate code.
6. If the request mentions a billing error, a charge dispute or a regulator, stop coding. It goes to the owner in the task at once.

Checks before you finish:
- The code is the customer's reason, with their words beside it.
- No suspicion is coded as a reason.
- "Not given" is used when no reason was stated, never a guess.
- A dispute or regulator mention is routed, not coded.

Example (invented, for illustration): "Requested 2026-09-23 by email: 'The price is too high for us, and we only booked three classes last month.' The words name price first and low use second. Coded: price. Note: low use also named; watch whether the next request says the same."
