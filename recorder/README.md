# Tico Recorder

Rust desktop V1, macOS first. The window is Tauri 2 on the system WebView (WKWebView on macOS), with a plain HTML/CSS page and TypeScript scripts in `ui/app` (no Chromium, Electron, framework, or bundler; see [The window's build](#the-windows-build)). `src/app` holds the Tauri commands and the `Recorder` controller the page polls. Capture, durable storage, transcription, and delivery run separately from the interface.

## Run

Requires Rust 1.92 or newer and the Tauri CLI (`cargo install tauri-cli --version "^2" --locked`) for bundles. On macOS, meeting/system audio requires macOS 14.2 or newer and the system's audio-recording permission. Microphone recording requires microphone permission.

```sh
npm ci                        # once, at the repository root: esbuild for the window's build
node recorder/build-ui.cjs    # after changing ui/ (or --watch); cargo tauri build/dev run it themselves
cargo run --manifest-path recorder/Cargo.toml --features desktop --bin tico-recorder
bash recorder/package-macos.sh
```

`package-macos.sh` runs `cargo tauri build` and writes `recorder/target/release/bundle/macos/Tico Recorder.app`. It signs with your Apple Development identity when one is in the keychain (set `TICO_SIGN_IDENTITY` to choose another), so keychain "Always Allow" and microphone permission survive rebuilds; without one it signs ad hoc. It is not notarized and makes no updater archive. It uses its own library, separate from the earlier recorder. `TICO_RECORDER_DATA_DIR` selects an isolated test library.

### The window's build

The page scripts (`ui/app/*.ts`, and the preview's `ui/preview/mock.ts`) are strict TypeScript, but the WebView runs JavaScript, so `node recorder/build-ui.cjs` strips their types into `recorder/dist/` (gitignored): `ui/app` → `dist/app`, the folder `tauri.conf.json` embeds (`frontendDist`), and `ui/preview` → `dist/preview`. It uses esbuild's per-file transform with the options `scripts/build-ui.cjs` gives Tico's own UI: no bundling, each file stays a classic script at the same path, so `index.html` lists `app.js` as before. HTML, CSS and fonts are copied as they are.

The build runs through Tauri's hooks rather than `build.rs`: stripping TypeScript needs Node and esbuild, and a Cargo build script that needs Node would break every `cargo` command on a machine without it. `cargo tauri build` runs it first (`beforeBuildCommand`). `cargo tauri dev` runs `node recorder/build-ui.cjs --watch` (`beforeDevCommand`, not waited on): one full build, then a rebuild of what changed on each save under `ui/app` or `ui/preview`, until dev stops. The window is embedded even in dev (the `tauri` dependency always has `custom-protocol`), so a save also makes `cargo tauri dev` rebuild and relaunch the app, which then embeds the new `dist/app`; restart dev after changing `build-ui.cjs` or the npm packages.

Each build ends by writing `dist/build-manifest.txt`: every source and output with an FNV-1a 64 hash, and the hashes of the recipe (`build-ui.cjs`, the root `package.json` and `package-lock.json`). With the `desktop` feature, `build.rs` (standard library only, `build_window.rs`) checks `dist/app` against it by content, not by time: a source changed, added or removed since the build, an output missing, altered or not from the build, or a changed recipe stops a plain `cargo build`/`cargo test` with the command to run, instead of embedding a stale window. While a watcher runs (`dist/.watching` holds its process id) the check waits up to ten seconds for it to catch up. Without the `desktop` feature (the CLI, most tests) nothing is embedded and Node is not needed. `scripts/tests/test_recorder_build_ui.py` covers the build and the watch; `build_window.rs` has the check's tests.

`ui/tsconfig.json` type-checks the page scripts with the DOM and no Node types (`python3 scripts/check_node_types.py`, the same strict options as `ui/tsconfig.strict.json`); the Tauri bridge is typed in `ui/types/bridge.d.ts`: every command the page invokes, with its arguments and reply, as the Rust `#[tauri::command]` functions take and return them.

The bundle is described by `tauri.conf.json` (product name "Tico Recorder", identifier `team.tico.recorder.native`, icons, macOS 14.2 minimum, hardened runtime), `Info.plist` (the microphone and meeting-audio usage text and the `tico-recorder://` link scheme) and `entitlements.plist` (audio input and network client; the app is not sandboxed). The identifier and the data folder `~/Library/Application Support/Tico Recorder Native` stay as they are, so microphone permission, keychain entries and recordings carry over from the earlier build. The folder name is read in `src/settings.rs`.

## Screen sharing and meeting links


People and More offer **Copy meeting link**. Copying a local recording first asks which Tico
will receive its transcript and confirms a private live meeting; it never makes the meeting
public. Add people in People so a private link works for them. Existing and ended meetings
open directly after sign-in. A filed recording links to its filed meeting. Links use Tico's
browser address, including when the recorder signs in through a runner hostname.

**Share screen** opens a confirmation naming the audience, then the macOS system picker.
A selected window or display is sent as a bounded live image feed (up to 5 fps, 1920 px),
for documents and slides. It is not a full-motion video transport. Screen images are never
saved or sent to bots. Recorder's own windows are excluded from display captures; if that
cannot be done on the OS version, or Screen Recording permission is absent, the picker offers windows only. Capture does not begin at launch,
on Record, on copying a link, or on reconnect. Other platforms currently report unsupported.

A red **Sharing · Stop** control stays available in other recordings and the library. Stop, Pause or Discard,
sending/finishing/deleting that meeting, sign-out, macOS stop and connection loss end the share.
Stop revokes the server share independently of uploads; sign-out and quit attempt this before releasing credentials. Slow uploads have a size-based deadline and an independent heartbeat; oversized frames are compressed further or skipped. A restart never resumes it. Making a meeting public while sharing asks to stop first; the
server also clears frames on visibility changes. An abandoned stream expires after ten seconds.
The viewer requires sign-in and current meeting access and clears images when access is lost. A separate status check clears stopped shares even while an image is downloading.

Older servers refuse the feature before the picker opens. Physical source selection, macOS permission prompts and the system clipboard require manual validation on a Mac.

## Releases and updates

- `.github/workflows/recorder.yml` builds a universal (Apple silicon and Intel) `Tico-Recorder_<version>_universal.dmg`, the updater archive `Tico-Recorder.app.tar.gz` with its `.sig`, and `Tico-Recorder.dmg`, a copy under a stable name for the download link. GitHub turns spaces in asset names into dots, so the release names have no spaces; the product name keeps its space. It uses the desktop app's signing and updater secrets (see `app.yml`). Notarization runs when the Apple ID secrets are set.
- A version tag gives the recorder that version (it is written into `tauri.conf.json` at build time). `release.yml` builds the recorder only when `recorder/` changed since the previous release; otherwise the previous release's recorder files are carried forward. Either way they are attached to the GitHub release, and `recorder-latest.json` is uploaded last, so the updater never sees a manifest whose files are missing. A release candidate's manifest is also put on the latest release when it is newer, so installed Recorders follow candidates too. A recorder failure leaves the server release in place.
- Download: `https://github.com/ticoteam/tico/releases/latest/download/Tico-Recorder.dmg`.
- Updates: the app reads `recorder-latest.json` on launch and every six hours, downloads a newer build in the background, and installs it once no recording is running and no live meeting is connected. A small banner (`ui/app/update.ts`) shows "Update ready · Restart", or "Updating after this recording" (or after the live meeting ends) while it waits. The Restart button does not override that wait. `update_check` and `update_install` are the commands behind it, and `status.update` in the view carries the state. Settings → Updates shows the version and **Check for updates** (Checking…, Downloading N%, Up to date, Update ready · Restart, or the error); the app menu's **Check for Updates…** opens it and checks. A copy that cannot replace itself (opened from Downloads or a disk image, so macOS runs a translocated read-only copy; on a `/Volumes` disk; or in a folder the user cannot write; see `src/app_location.rs`) does not check: the row and a one-time dismissible banner offer **Move to Applications**, which copies the app to `/Applications` (or `~/Applications`) without the quarantine flag, quits and opens the moved copy. A newer copy already there is replaced only after asking (`move_to_applications`).
- Pull requests that change `recorder/` build the window (`node recorder/build-ui.cjs`) and run `cargo test --locked --features desktop,cli` on macOS (`.github/workflows/pr-checks.yml`).

## Workflow

- First run, with no org and no recordings, is the sign-in screen: it lists the orgs the Tico desktop app is signed in to (`view.desktop_orgs`), each with Allow (`sign_in_desktop` with that org's `url`); Another Tico, or a Mac without the desktop app, types an address.
- The library is a Recordings list with search, Coming up (calendar events with Record), and recordings grouped by day. Each row shows its org's tile (or This Mac), time · length · org (or This Mac only), and a pill only when it says something: Live, In Tico, Transcribing N, Needs retry. Recordings only on this Mac have Save to Tico, which opens Finish. Delete (hover trash) asks first. The floating Record pill starts a recording; its caret picks audio sources. The org pill in the top bar changes the default org.
- Sheets and menus close with Esc, innermost first. Esc on a meeting or Settings goes back to the library; ⌘F searches the transcript, ⌘T shows or hides it, ⌘, opens Settings.
- A meeting is Tasks and Notes on the left, with the stop/levels/timer bar while recording, and the Transcript sidebar on the right. The top bar has Share live, Finish and More (Share screen, Copy meeting link, Pause/Resume sharing, Audio details, Retry failed, Copy transcript, Show/Hide transcript, Discard live share, Delete recording).
- Ask Tico about this meeting, at the foot of the transcript, is private: questions go through the Tico router (`POST /api/v2/meeting-assist`), create no Tico meeting, and the answers sit between the turns as cards only you see. There is no meeting chat in the Recorder.
- Recordings made in this session get task and doc-change suggestions from new speech every 10 s once 400+ characters accumulate (streamed text counts, so suggestions follow the conversation within seconds), plus once after Stop when transcription settles. A suggestion's quote is checked against the text it was drafted from, so a later chunk that rewords streamed text does not drop it. Suggestions arrive unselected, with an editable owner when the transcript identifies who should do the work. Owners come only from the meeting org’s roster; unclear ownership stays blank. A Tico without the suggestion endpoint gets a plain "needs a newer Tico" note instead of retries. Hand-added tasks and doc changes pick their supporting quote from the transcript.
- The transcript is rebuilt from word timings: the microphone is "Me", meeting audio is split into the voices found on this computer after Stop ("Speaker 1", "Speaker 2", …; one voice keeps "Meeting audio"), and everyone's speech is ordered by when it was said. Consecutive speech from one speaker is one block, split into paragraphs at pauses and long finished sentences. Matching runs of at least three microphone words that repeat meeting audio within a second (the call playing on speakers) are dropped; one misheard word, an extra fragment ("a", "f-") or a missed word inside a run does not end it, and "gonna"/"going to" match. Those runs measure the echo's delay on this call (the median offset, a few milliseconds on built-in speakers); a one- or two-word repeat is dropped only within 150 ms of that delay, so echoed "um", "you know" or a word opening the next chunk goes while a reply said back ("yes" to "yes") stays. Echo straight after removed echo in the same utterance may sit up to 3 s from a streamed reference's slipping word times. Punctuation a stream sends as its own word goes with its nearest word. Other unmatched words stay; `tico-recorder-cli echo-replay <recording.json> [--streamed <words.json>]` replays these rules on a recording and its streamed words. Speaker labels use anarlog's pyannote port (`vendor/anarlog`, CoreML on macOS, about 80 s per hour of meeting), combined with Scribe's own per-chunk speaker turns, which are joined across the meeting by voiceprint; new meeting-audio words find them again. Storage chunks, silent intervals, and chunks with no recognized speech do not become conversation rows. Audio status and transcription retry details sit behind the Audio toggle above the transcript; transcript rows have no quote or playback controls. A line already shared live can be edited or removed (below).
- Live text: while recording, each input also streams to xAI (`grok-voice-transcribe-2.0`, 100 ms frames) so words appear within about a second; meeting audio gets the service's provisional speakers (S1, S2, …). On by default when an xAI key is saved in the keychain (account `xai`); `streaming`, `streaming_url` and `streaming_model` in settings.json change it, and language follows Settings › Language. Final streamed words are saved locally (`live_words`), partial text is kept in memory. Chunk transcripts replace streamed text for their time range once done and stay the transcript of record. A live meeting gets each streamed final within about a second, so bots hear it; when the chunk is transcribed its words correct those turns (each word goes to the streamed turn it falls in, or the nearest; words past the last streamed turn are new turns), so nothing is shared twice. A line already shared live can be edited or removed in the transcript: each change goes up as that line's next revision, and a removed line reads "[removed]" in Tico. A person's edit wins over any later automatic correction from the finished transcript. Saving holds edits to that meeting from its last pass until it ends, sends the changes first, and refuses to file if one could not reach Tico. Without live text, or after it drops, finished chunks are shared as before. With Your Tico, live text and transcription go through the default Tico; drafting goes through the recording's org (`/api/v2/recorder/...`) with your own sign-in, so no keys of your own are needed; `speech_source` in settings.json (`tico` or `own`) chooses between them, and an install that already had keys of its own keeps them. Streaming never slows capture: a full queue (10 s) or a reconnect skips streamed audio only.
- Microphone and system audio are stored as independent, timestamped WAV chunks of 30–55 s, cut at the quietest pause in that window so words are not split. Long chunks give the model context; see `bench/README.md`. Failed transcriptions retry automatically twice (15 s, then 60 s), then wait for Retry. An input that stops delivering frames for 3 s is flagged. Audio survives transcription/network failures. Stop releases inputs and flushes the final buffer. Missing inputs, silence, device errors, and dropped frames remain visible.
- If microphone setup fails, meeting-audio setup is still attempted. The surviving input records; failures of both inputs preserve both causes. Device-error warnings identify the input and appear under the Audio toggle.
- Each input joins the capture loop as soon as it is ready. Microphone audio keeps saving while system-audio setup or permission is pending. Stop closes active inputs without waiting for a pending initializer; an input that finishes connecting after cancellation is closed immediately. Empty captures show No audio, and background Tico-delivery failures are visible in the library and meeting workspace.
- Settings holds input selection and transcription endpoint/model. Tico connects with Sign in with Tico: type the address you use in the browser (filled in from the Tico desktop app), choose Allow in the browser, and the recorder gets its own token, renewed hourly for 90 days and revocable under Settings › Computers › API tokens in Tico. Runner addresses are found automatically. The Tico Recorder tile on Tico's Meetings page opens `tico-recorder://connect?server=…`; the recorder asks before signing in. Tico asks the recorder to record with `tico-recorder://record?server=…` links of two kinds. A Tico call (a Google Meet started in a thread, docs/dev/meet-calls-contract.md) sends `call=<call id>`: the recorder claims the call's recording source (`POST /api/v2/calls/<id>/recorder`) and, when it is the source, records into the call's own live meeting under the call's title; the recording stops by itself when the call ends, has no Finish, and Stop gives the source back. Join on a Tico calendar event sends `title=…&event=<occurrence id>`: the event id is required (a link with only a title is refused). The recorder first reads the occurrence from Tico (`GET /api/v2/calendar/events/<occurrence id>`) and records only if Tico shows it, its `can.join` is true and now is between 15 minutes before its start and its end; otherwise it does nothing and logs why. It then records a private live meeting named with Tico's title for the event (the link's title is never used), sending `calendar_event` so Tico links the meeting to it (an older Tico that refuses the field gets the meeting without it). Both kinds behave the same around sign-in: for an org the recorder is signed in to it starts at once, without asking; for another org it asks to sign in first (the request is dropped after five minutes, when the sign-in is dismissed or replaced, or when another org signs in), then asks once "Record <title>?" with Tico's title, and records only on Record (Cancel gives a call's source back). A recording already running stays the only one: an event link shows it instead, and a call link asks to stop it first. Several Ticos can be connected: the default is preselected in Share live and Finish, which offer only orgs that do not have the meeting yet, and Sign out ends that Tico's sign-in. Secrets use the operating system's credential store. The saved microphone WAVs and chunk transcription always use unprocessed mic audio. On the built-in Mac mic/speaker route a separate macOS voice-processing engine aids live text (minimum audio ducking, AGC off). Configuration changes rebuild capture on the new route; a voice-processing restart failure leaves plain capture running. Headphones and unsupported routes use plain capture. Mic text waits for meeting audio, with an eight-second bound; terminal reference failures, mic-only capture and Stop release it. After Stop, live sharing holds both inputs behind unfinished chunks until completion, terminal failure or 90 s past the chunk's end. Finished reference ranges replace streamed references. Late transcription uses the last shared start time when needed to keep delivery ordered; the local transcript retains capture timestamps. Validation refusals read back and repair the pending outbox once per outbox state before retrying; only Tico's time-order refusal is final for a correction. Remote Speaker labels are persisted under stable voice/turn ids before display and keep their numbers across new voices, stream-to-batch voice aliases, diarization and reopening. The default STT is ElevenLabs Scribe v2 through OpenRouter's transcription API, asked for word timings and, on meeting audio, speaker labels (settings still on the earlier Muse default move to it); speech defaults to English (Settings › Language, empty to auto-detect); meeting text inference uses the Tico gateway.
- Recording and transcription happen before a meeting is sent to Tico. Audio goes to the configured transcription provider. Starting a recording does not automatically create or share a Tico meeting.
- Nothing reaches Tico until Share live or Copy link in the Share live sheet. The sheet picks the org, who can join (Anyone on the org, or Only people I add, the default) and people or bots to add; picks wait until Share live. The meeting then streams into Tico as a live meeting; once live, changes to who can join apply at once. An older Tico that cannot keep a meeting private refuses, so nothing is opened to the team by accident. A durable ordered outbox retries lost acknowledgements. Background delivery continues when another recording or the library is visible.
- Settings → Use my Tico calendar uses the existing Tico calendar connector and your own roster email. It refreshes enabled calendar context every minute and marks stale results. Recording a calendar event uses its title/invitees; invitees are not treated as verified attendees or identified speakers.
- Google Meet and Teams names (macOS): while a recording includes meeting audio, a read-only Accessibility adapter scans Meet-titled windows in Chrome, Arc, Edge, Brave and Safari: every 2 s until it finds a Meet document, then four times a second. It switches on Chromium's page accessibility (`AXManualAccessibility`), whose tree is otherwise empty, and switches it back off when the recording ends unless it was already on. Participant names come from video tiles and People-panel rows; who is speaking comes only from the level indicator in a People-panel row, so it needs the People panel open, and only when the local person's row is known (marked "(You)", or the one row without a mute control); otherwise rows give names only. Silences under 0.7 s stay one turn; missed or unreadable polls end it. Each "Speaker N" label (one voice across chunks and the live stream) gets a name after at least 1 s of overlap with two thirds for one name, covering at least 40% of that voice's speech while indicators were readable; otherwise it stays "Speaker N". A name sticks: it changes only when another name wins, and never goes back to "Speaker N". A speaker a person typed is never renamed. The local person is never a remote name, and the mic stays Me. The live view, live Tico revisions and saved transcript use the same names; renames already shared go out at most 20 queued at a time, and a rename Tico refused is not sent again. Observed participants accompany Save. During a recording with a supported browser open, a dismissible notice offers Allow for Accessibility; Settings › Audio has the same Allow. The first Allow shows macOS's prompt, later ones open the Accessibility pane. Chat, captions, presentation text and screenshots are excluded. The Meet class names live in one table (`speaker_names/meet.rs`); if they change, nothing is named. See [AX fixtures and what is still unverified](tests/fixtures/meet-ax/README.md). Microsoft Teams on the web (`speaker_names/teams.rs`) works the same way in windows titled like Teams on teams.microsoft.com, teams.live.com or teams.cloud.microsoft, read four times a second only while video tiles show: names come from video tiles (a shared screen's extra tile is skipped, guests' "Unverified" dropped), who is speaking from the overlay Teams marks `vdi-frame-occlusion` on a speaker's tile, and only when the local tile is known (the one tile without that overlay); without tiles nothing is named. Zoom has no adapter yet. Browsers expose only the front tab's page: while no call document is found, the watch reads other browser windows' tab strips (tab titles only, at most every 10 s and 300 nodes) and, when a Meet call ("Meet - …") is in a background tab, logs it once and shows "Bring the Meet tab to the front to show who's speaking" until the document is found or the tab is gone. Teams keeps one tab title for chat and calls, so it gets no such notice.
- Log: `recorder.log` in the library folder (rolled to `recorder.log.1` past 1 MB) records, per recording, the meeting watch (Google Meet, or Microsoft Teams on the web): accessibility state, page accessibility switched on and back off, a Meet call in a background tab, the Meet or Teams document found or lost (browser, windows walked, nodes, poll time p50/p95 each minute), Meet's People-panel rows or Teams' video tiles and how the local one was found (marker, structure, or none so no speaking state), each speaking turn per name, each voice label's vote when a name is assigned, changed or withheld (overlap per name, share, coverage, reason), and live correction counts and refusals. Noisy lines are rate-limited. It holds names the meeting shows, never transcript text.
- Settings › Orgs lists the Tico desktop app's orgs that this recorder is not connected to yet, each with Connect. While any are not connected yet, the org menu lists them too. Type a Tico address under Other address to connect a Tico that is not in that list.
- Bot questions run in explicit circuits, three context reviews at a time. A full circuit repeats bounded batches. Direct reports go first. Coverage distinguishes waiting, running, questions, no questions, interrupted, and failed reviews. This mode bypasses full-agent dispatch on transcript/chat messages.
- Tasks: **Link** searches the meeting org’s tasks by title or #number, selects several, and queues links without creating work. The note-taker can match speech to one of up to 30 active tasks assigned to the recorder; its proposal offers **Link #N**. Task access, active status and ownership are rechecked before using a cached candidate; accepting a link rechecks read access. A suggested task shows its title, time and owner; a created task's row opens it in Tico for full editing. On Save, approval and notes precede item receipts, then links go in batches of 20 with a durable receipt per task; retries resume acknowledged batches. Each Link and Unlink action has its own persisted retry key. Pending links resume when the app starts or a recording opens, and retry with backoff when the connection returns, even with the recording closed; links waiting for Save show the task status, and a spinner appears only during a link request. Background receipts refresh the open meeting without reopening it; a failed request shows a short error on the task row. Unavailable targets are skipped without task details. Create after Save applies the current title, owner, details and due date against the saved item version; the server keeps tasks private for private or Participants-only meetings. Older drafts keep their saved due date and details, which Create still sends. This Mac deletes a meeting filed for review, removes its delivery receipt and discards the live transcript, chat and events. It also drops queued links and hides Link controls and proposals; recovery cannot finalize the discarded live share or send its links. The local recording and transcript stay, and tasks already sent remain unchanged. An older Tico without discard ends the meeting and reports that its live transcript remains until Tico is updated.
- Tasks: suggested tasks and doc changes are proposals (dashed box, light green) with supporting transcript quotes. Create files one as a private task in Tico once it has an owner, and it then shows as a task with its number; × dismisses it; + Add writes one by hand. Document changes create a review task through Tico's existing document-update flow; they do not edit documents automatically. Saving a meeting does not create its proposals.
- Pause sharing keeps capture running locally. Paused capture-time words never enter the shared outbox, including finished-chunk corrections after Resume, retry or recovery; Saving files only shared words. Without word timings an overlapping chunk stays local in full. A pause first discovered in Tico has no capture timestamp, so the uncertain interval since the last acknowledged capture stays local conservatively; queued turns keep their sequence numbers as removal markers. Resume sharing before saving so pending public words upload before filing. Saving requires review of kept titles and quotes on recordings with paused speech, including reworded text. This conservative warning covers every kept item on those recordings; it does not guess whether a common word or paraphrase is private. Discard live share (after Stop) ends the shared meeting without filing it and keeps the local audio and transcript; a failed Discard stays visibly pending and can be retried. With no acknowledged capture at a remotely discovered pause, the uncertain interval starts at zero; this deliberately withholds earlier public words rather than risk sharing paused speech.
- Create also requires Resume and is disabled after Discard. If a recording contains pauses, a task with a title or quote asks twice (Create anyway), rechecked after edits. Its surrounding transcript always omits paused speech; the review covers the title and quote, not hidden neighboring lines.
- Finish names the recording and saves it: to This Mac, or to an org for the org or Participants only (the recorder, people who joined live and people added). A meeting shared live only with the people added defaults to Participants only. Saving to an org ends a live meeting first and approves the finalized record; paused speech asks Save anyway. Delete in Finish asks first. Retries preserve one canonical meeting and durable task receipts. Discard live share keeps the recording on this Mac and removes what was said from Tico; it can be saved to Tico later as a meeting recorded here.
- Empty or silent shared sessions can be ended without creating a fabricated imported meeting. Closed sessions and recordings whose delivery has begun cannot reopen capture; retries keep the original frozen transcript.
- Settings → Import an older recorder library copies existing recordings, transcripts, action drafts, destination metadata, and delivery receipts. Source audio and metadata are not modified. Credentials must be saved in the native app's keychain separately.

## Tico server integration

Every call to Tico carries `X-Tico-Recorder-Version` (the release's version, read from `tauri.conf.json` by `build.rs`)
and `X-Tico-Recorder-Install`, a random id for this copy kept in `install-id` in the library folder; speech and chat
providers never get them. Tico shows the version to owners and admins and offers an update link on Meetings
(docs/meetings.md, Tico Recorder).

Use the companion `codex/meeting-questions-v1` worktree. It adds question-mode sessions, gateway-only context reviews, serial Jev classification, and quoted proposals while preserving existing live-meeting endpoints.

Configure the server's existing Tico gateway connection, plus `TICO_MEETING_QUESTION_MODEL` with a **published Tico gateway model profile** for the fast meeting agent. The intended upstream is Mercury 3. This repository does not publish that profile or assume it exists. With no profile/key, the feature fails closed and never falls back to a direct vendor. Deduplication uses the gateway's existing Decide endpoint.

## Validation

```sh
cargo test --manifest-path recorder/Cargo.toml --features desktop,cli
# In the companion Tico checkout, with its test environment:
TICO_NATIVE_CLI=/absolute/path/to/recorder/target/debug/tico-recorder-cli \
  .venv/bin/python -m pytest backend/tests/test_native_recorder.py -q
```

The native tests cover shared-line edits and removals (one revision each, retries, a person's edit kept over a later automatic correction, saving refusing an edit Tico never received), audio filtering/resampling, silence, queue overflow, recovery, exclusive STT claims, legacy migration, lost import acknowledgements, ordered live delivery, explicit output creation, and the desktop review/share controls. `ui/preview` runs the page against a mock `invoke` with fixture scenes, served from `dist/preview` once built; `node ui/preview/shoot.mts` (Playwright WebKit, `PLAYWRIGHT` pointing at a playwright install) builds the window, then renders them at 1040×690 and 760×490 in light and dark into `ui/screenshots/` and checks delete confirmation, Create and dismiss on tasks, Share live staging, Finish audience and title, sign-in, @mentions, transcript search, Ask and Esc. The Tico integration replay runs the native executable against a local Tico server and synthetic STT/gateway fixtures, including finalization and task retry.

For the opt-in Pause/Resume/Discard replay, build `tico-recorder-cli` with `--features cli`, then run `TICO_NATIVE_CLI=/absolute/path/to/tico-recorder-cli python3 -m pytest backend/tests/test_native_recorder.py -q -n 0 -m slow`. It starts an actual isolated Tico backend and drives the production native store/transport with synthetic timed words and WAV buffers. It uses no capture, provider, bot attachment or bot run; reviewed action items go to a synthetic human. The hidden `privacy-replay-test` driver requires loopback and an explicit isolated library. This replay does not replace installed desktop or real Mac capture checks.

The 200-context test verifies circuit scheduling, first-layer priority, coverage, grouping, and contribution preservation with synthetic inference. **It is not evidence of real routed model latency, cost, or quality.** Fresh device/meeting checks, the published Mercury profile, and the real 200-context gateway sweep remain release gates. Windows/Linux system-audio capture, voice participation, onboarding voice, calendar OAuth inside Recorder, and automatic document editing are outside this V1.

### Meeting transcription benchmark

`bench/meeting_bench.py` runs the CLI's `transcribe-meeting` (the app's chunking, real STT, echo removal and speaker labels) on four AMI meetings and scores word error rate per side and speaker-attributed WER. It is opt-in and paid (about $0.50 a run); see `bench/README.md`.

```sh
TICO_RECORDER_STT_KEY=... uv run recorder/bench/meeting_bench.py --check
```

### Real transcription gate

Build the CLI, then run the generated-speech check on macOS:

```sh
cargo build --manifest-path recorder/Cargo.toml --features cli --bin tico-recorder-cli
python3 recorder/tests/real_transcription.py \
  --cli recorder/target/debug/tico-recorder-cli \
  --output /absolute/private/validation-directory
```

Provide `TICO_REAL_RECORDER_STT_KEY` through the caller's environment, or explicitly add `--keychain` after saving a transcription credential in native Settings. No key is accepted in command arguments or written to the report. The check reads native transcription endpoint/model settings; it requires a remote HTTPS endpoint and does not write to the meeting library. Without a credential, it exits unsuccessfully and saves a `not_run` receipt. It never starts a microphone/system-audio input or plays sound.

The check generates a short WAV through macOS `say`, submits it through the production transcription adapter, and saves recognized/expected words, whole-response latency and word error rate in a mode-600 receipt. A pass requires word error rate ≤0.25. This proves fixture recognition through the configured real provider; it does **not** prove physical capture, live first-turn latency, Tico delivery, or the 200-context router gate. Keep the validation directory private; receipts contain fixture transcript text. The CLI's `verify-transcription` command can also check another short WAV with explicit expected text.

For an explicit loopback test gateway, the diagnostic CLI accepts `--local-test-gateway` and records that transport separately. The companion Tico tool `scripts/meeting_test_gateway.py` configures an isolated native test profile and supplies a generated gateway test key. Its real OpenRouter key remains in the server process. This verifies the same native STT adapter through the gateway; it does not configure the person's Recorder library or claim a hosted gateway exists. The test gateway also exposes a speech profile and validates returned TTS audio without playing it.

For an authorized credential migration, the signed desktop executable accepts `--import-transcription-key-stdin`. This mode reads one bounded credential from standard input, saves and verifies it using the native app's own keychain identity, and exits without opening capture, a window or the meeting database. It preserves an already configured native credential. The normal setup path is Settings; automation must never put keys in arguments, source files or logs.
